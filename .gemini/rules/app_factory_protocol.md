# App Factory Custom Rule

앞으로 모든 새로운 앱 개발을 시작하거나 기존 앱에 기능을 추가할 때는 반드시 아래의 **'앱 공장(App Factory)' 모듈화 원칙**을 준수하여 코드를 작성해야 합니다.

1. **Config-Driven Architecture (설정 기반 아키텍처):**
   - 앱의 핵심 텍스트, 테마(색상), API 주소, 사용할 모듈의 On/Off 여부는 절대로 코드 내에 하드코딩하지 않습니다.
   - 반드시 외부 설정 파일(`config.json` 또는 `.env`)을 통해 런타임 또는 빌드 타임에 주입받아야 합니다.
   
2. **Server-Side UI / Module Assembly (서버 조립 및 공통 모듈화):**
   - 공통 기능(로그인, 결제, 공지사항 등)은 해당 프로젝트 안에 종속되게 짜지 않고, 독립된 패키지나 모듈 형태로 분리합니다.
   - 해당 앱만의 "특수 기능"을 제외한 모든 공통 기능은 서버(또는 패키지 저장소)에서 받아와서 메인 앱에 레고 블록처럼 '조립'하는 구조를 지향합니다.
   
3. **Core vs Feature 철저한 분리:**
   - 앱 고유의 비즈니스 로직(특수 기능)만 로컬 프로젝트의 `features/특수기능/` 폴더 내에 작성합니다.
   - 그 외의 기본 UI 컴포넌트, 네트워크 모듈, 인증 모듈은 모두 `core/` 모듈로 격리하여 다른 프로젝트에서도 그대로 복사/붙여넣기하여 즉각 재사용할 수 있도록 독립성을 보장해야 합니다.

4. **무관용 다국어(I18n) 원칙:**
   - 앱 화면에 보여지는 모든 텍스트는 절대 위젯 코드 내에 한글이나 영어로 하드코딩하지 않습니다.
   - 모든 텍스트는 `lib/core/translations/app_translations.dart` 사전에 등록한 뒤, 반드시 `GetX`의 `.tr` 메서드를 통해서만 호출해야 합니다.

5. **모듈 구조도 현행화(Documentation) 원칙:**
   - 새로운 공통 모듈(패키지)이나 기능 단위가 추가될 때마다, 반드시 `app_modules_structure.md` 문서의 표와 트리 구조에 해당 내용을 기입하여 최신화(현행화)해야 합니다.
   - 이를 통해 앱 공장의 전체 구조와 부품 리스트를 항상 한눈에 파악할 수 있도록 유지합니다.

6. **시크릿 키 관리 원칙(Secret Key Management Principle):**
   - 모든 서명 키(Keystore)와 스토어 API 키(JSON), 비밀번호 프로퍼티 파일은 반드시 프로젝트 루트의 `keys/` 폴더 내부에 격리하여 보관해야 합니다.
   - 깃허브(Git) 등 원격 저장소에 위 파일들이 절대 올라가지 않도록 강력하게 차단합니다.
   - 안드로이드 빌드(`build.gradle`) 및 Fastlane 배포 스크립트는 항상 `keys/` 경로를 기본 참조하도록 설계해야 합니다.
